# Независимая проверка (read-only верификатор)

Верификатор — отдельный агент без права записи в проект. Он посчитал всё по DECISIONS.md своим скриптом, не импортируя и не копируя `report.py`, сравнил с CONTROL_SUMS.md и с выводом программы, проверил инварианты на каждый день и прогнал тесты. Ниже его отчёт без изменений по существу; в конце — что сделано по замечаниям.

## Метод
- Расчёт написан с нуля в scratch-каталоге. Суммы разбираются из строки сразу в целые копейки, float не используется.
- Правила взяты из DECISIONS.md:
  - статус работы — только по датам, дата отчёта включается;
  - платёж выплачен, если `paid_at` ≤ D и он не возвращён к D;
  - платёж в очереди, если `created_at` ≤ D и он не оплачен к D;
  - у отменённой работы к оплате 0;
  - привязанный платёж идёт в свою работу, излишек — в пул;
  - пул распределяется сначала на принятые работы по (`completed_at`, номер), затем на запланированные по номеру; что осталось — переплата;
  - договоры, подписанные позже D, исключаются.
- Сравнение с выводом `python3 -I report.py --date D --csv …`: текст и CSV, разобранный в копейки. С 2026-08-01 по 2026-12-31 программа запускалась на каждый день (153 запуска).

## Инварианты
- По 153 дням и всем договорам, в расчёте верификатора и в выводе программы, выполняются везде:
  - `Σpaid + overpaid = net`;
  - `net + remaining = payable + overpaid`;
  - `0 ≤ paid ≤ due` по каждой работе.
- Покомпонентно расчёт верификатора совпал с программой во всех 153 днях.
- `Σpaid ≠ net` бывает только у D-2 с 2026-11-12 (95 000 против 90 000), как и задумано.

## Замечания верификатора
1. **Средняя.** Строка CSV с лишним полем роняет программу с трейсбеком (`AttributeError`), а решение 16 обещает список ошибок.
2. **Низкая.** Формат проверяется мягче, чем описано: принимаются сумма `1e2` и дата `20260201`.
3. **Низкая.** Ошибки-последствия: если строка договора или работы с ошибкой, ссылки на неё дают ещё «не найден».
4. **Низкая.** Нарушение инварианта даёт трейсбек вместо понятного сообщения.
5. **Низкая (док.)** Не описано, что «после очереди» может быть отрицательным и что платёж в очереди, привязанный к отменённой работе, входит в «в очереди».
6. **Низкая (док.)** В решении 8 фраза «итоги по договорам не меняются» неточна для варианта (в).
7. **Инфо.** В CONTROL_SUMS для 12.11 нет строк «Сумма договора», «Отменено», «Осталось после очереди».
8. **Инфо.** Возврат в день оплаты в DECISIONS не упомянут.

Не покрыто тестами: лишние поля в CSV, возврат в день оплаты, два привязанных платежа на одну работу, натуральная сортировка (W-9 раньше W-10), платёж в очереди, привязанный к отменённой работе.

Найденные расхождения README с поведением кода:
1. `--csv` в несуществующий каталог — трейсбек после вывода отчёта.
2. CSV не в UTF-8 — трейсбек `UnicodeDecodeError` без файла и строки.
3. `--data` по умолчанию берётся от текущего каталога, это не было сказано.

Решение: в финальном проходе код не меняется (так было условлено), поэтому README приведён в соответствие с фактическим поведением — все три случая описаны. Исправление в коде — перехватывать `OSError` и `UnicodeDecodeError` в `main` и выводить полный путь — оставлено на потом.
