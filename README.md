# Отчёт по оплате работ и договоров на дату

Скрипт на Python, только стандартная библиотека, ничего устанавливать не нужно. Запускался на Python 3.14. Рассчитан на 3.9+, но на других версиях не проверялся.

## Запуск

```bash
python3 report.py --date 2026-11-10                 # отчёт в консоль
python3 report.py --date 2026-11-10 --csv out.csv   # плюс CSV-файл
python3 report.py --date 2026-11-10 --data path/to/data
```

- `--date` — дата отчёта, `ГГГГ-ММ-ДД`. События этого дня учитываются.
- `--data` — папка с `contracts.csv`, `works.csv`, `payments.csv`. По умолчанию `data` относительно текущего каталога, поэтому запускайте из корня проекта или передайте путь явно. Файлы должны быть в UTF-8, как в выгрузке.
- `--csv` — дополнительно сохранить отчёт: по строке на работу (`level=work`) и на договор (`level=contract`). Суммы в CSV записаны с точкой, без разделителей разрядов. Каталог для файла должен существовать.

## Проверка данных и коды возврата

| Код | Когда |
|---|---|
| 0 | отчёт построен (предупреждения, если есть, выводятся в stderr) |
| 1 | ошибка в данных, отчёт не построен (а также сбой Python, см. ниже) |
| 2 | ошибка аргументов: нет `--date` или дата не в виде `ГГГГ-ММ-ДД` |
| 3 | внутренняя ошибка: нарушен инвариант расчёта |

Ошибки данных (полный список — решение 16 в DECISIONS.md) выводятся в stderr все сразу, с файлом и номером строки:
- лишние или недостающие поля в строке CSV;
- сумма не в виде `123` или `123.45` (например, `1e2`) либо ≤ 0;
- дата не в виде `ГГГГ-ММ-ДД` (например, `20260201`);
- дубли номеров и ссылки на несуществующие договоры или работы;
- статус, который противоречит датам в той же строке.

Если отсутствует целый файл или обязательная колонка, программа останавливается сразу, не проверяя строки. В сообщении «файл не найден» указано только имя файла — проверьте `--data`.

Чего программа не обрабатывает (сейчас — трейсбек Python и код 1): CSV не в UTF-8; `--csv` в несуществующий каталог (отчёт при этом уже выведен в консоль).

Статус в выгрузке может быть «новее» даты отчёта: например, на 10.11 упаковка W-23 ещё не принята, а платёж P-8 ещё не создан. Это не ошибка: состояние на дату восстанавливается по датам событий.

## Как читать отчёт

- Возвращённый платёж учитывается только между днём оплаты и днём возврата. Если возврат в тот же день, платёж не учитывается совсем.
- «В очереди» — неоплаченные платежи, в том числе привязанные к работе, даже если она отменена.
- «Осталось после очереди» = осталось − в очереди. Отрицательное значение значит, что оплата всей очереди даст переплату на эту сумму.
- «Переплата» — выплачено больше, чем стоят работы по договору.

## Что осталось и что бы я сделал дальше

- Транскрипт `/export` к сдаче прикладывается отдельно.
- Перехватывать в `main` ошибки чтения и записи (CSV не в UTF-8, `--csv` в несуществующий каталог), чтобы выводить понятное сообщение с полным путём вместо трейсбека.
- Когда бухгалтер ответит на вопросы из [NOTE_TO_ACCOUNTANT.md](NOTE_TO_ACCOUNTANT.md), поправить правила, о которых идёт речь: P-3 и P-7 — в счёт работ или сверх них, учёт отмены W-13. Если такие случаи будут повторяться, ввести в выгрузке признак «сверх цены работ», а не угадывать по назначению платежа.
- Показывать в отчёте, какими платежами закрыта каждая работа (колонка «Откуда деньги» из CONTROL_SUMS.md), чтобы распределение было проверяемым.
